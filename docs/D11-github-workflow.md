## Branch naming (Conventional Branch)

```
<type>/<TICKET-ID>-<kebab-summary>
```

| Type | Use when |
|------|---------|
| `feat` | New feature or test coverage for a new feature |
| `fix` | Bug fix or defect remediation |
| `test` | Adding or updating test cases without a feature change |
| `chore` | Non-functional: config updates, doc fixes, dependency bumps |
| `ci` | CI workflow changes |

Examples:
```
feat/STORY-AUTH-204-sso-plus-email
fix/DEF-AUTH-0017-sso-callback-500
test/TC-AUTH-031-add-sso-e2e
ci/INFRA-009-add-nightly-regression
```

Rules enforced by `qa-github-spv`:
- No uppercase in branch names
- Ticket ID segment must match an existing run artifact ID or Taskmaster task
- Summary segment ≤ 50 characters, kebab-case only

## Commit conventions (Conventional Commits 1.0)

```
<type>(<scope>): <imperative summary>

[optional body]

Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
```

- Summary line ≤ 72 characters
- Scope = module abbreviation (e.g., `auth`, `billing`, `ui`)
- Footer always includes `Co-Authored-By` with the model name — never "Aegis"
- Breaking changes: add `!` after scope and a `BREAKING CHANGE:` footer

Examples:
```
test(auth): add SSO regression for plus-aliased emails

fix(auth): reject malformed SSO callback (closes DEF-AUTH-0017)

feat(billing)!: replace Stripe v1 with Stripe v2 SDK

BREAKING CHANGE: webhook signature verification format changed
Co-Authored-By: Claude Sonnet 4.6 <noreply@anthropic.com>
```

## PR description template

`qa-github-planner` drafts PR descriptions using this structure:

```markdown
## Summary
- [what changed and why — 1-3 bullets]

## Test coverage
- [which test cases this PR adds or modifies]
- [RTM rows affected: TC-AUTH-031, TC-AUTH-032]

## Defects addressed
- [DEF-AUTH-0017 — link to defect record]

## Gate status
- [ ] TESTING gate passed (`/qa-gate-check --stage=testing --run={id}`)
- [ ] SPV review: `review.passed`
- [ ] No open Sev1/Sev2 defects

🤖 Generated by Aegis automated pipeline
```

## GitHub issues for defects

When `defect.opened` fires with `tracker: github`, `qa-github-implementer` creates a GitHub issue:

- Title: defect title (max 65 chars, from defect record)
- Labels: `bug`, `severity:{sev}`, `priority:{pri}`, `module:{module}`
- Body: reproduction steps + evidence links from the defect record
- Linked to the run PR via `Closes #N` or `Refs #N`

The issue URL is written back to the defect record as `trackerUrl`.

## `gh` CLI usage patterns

```bash
# Create branch
git checkout -b feat/TC-AUTH-031-add-sso-e2e

# Open PR
gh pr create --title "test(auth): add SSO E2E coverage" \
  --body "$(cat pr-body.md)" \
  --label "test,module:auth" \
  --reviewer @qa-lead

# Link issue to defect
gh issue create --title "DEF-AUTH-0017: SSO callback returns 500" \
  --body "$(cat defect-body.md)" \
  --label "bug,severity:2,priority:1,module:auth"

# Check CI status
gh run list --branch feat/TC-AUTH-031-add-sso-e2e --limit 5
gh run view <run-id> --log-failed
```

## SPV validation checklist (`qa-github-spv`)

Before a PR is marked ready for review, `qa-github-spv` verifies:

- [ ] Branch name matches Conventional Branch format
- [ ] All commits match Conventional Commits format
- [ ] PR description has Summary + Test coverage sections
- [ ] `Co-Authored-By` footer present on all commits
- [ ] No framework-internal names in PR title or description (brand-clean)
- [ ] CI checks green (or failing CI has a known flake quarantine)
- [ ] No unresolved `requested-changes` from prior SPV reviews
